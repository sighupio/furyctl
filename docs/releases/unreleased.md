# furyctl release vTBD

Welcome to the latest release of `furyctl` maintained by SIGHUP by ReeVo team.

## New features 🌟

### All kinds

- [[#808](https://github.com/sighupio/furyctl/pull/808)] When a tool that furyctl runs fails, the error now starts with the cause, for example each Ansible host that failed or does not answer, then gives the command and the last lines of its output. furyctl saves the full output to a text file in `.furyctl/logs` and gives its path. Before this release, the error repeated the name of the command and gave its full output, and the cause was difficult to find in it.
- [[#392](https://github.com/sighupio/furyctl/issues/392)] `furyctl diff` now prints a CONFIG table. The table has one row for each changed field, and the rows are grouped by phase (General, Infrastructure, Kubernetes, Distribution, Plugins). The columns are FIELD, CURRENT, NEW and RULE, and a first line gives the number of changes. The order of the rows is the same on every run. A list item shows its name or its host name, not its position.
- [[#392](https://github.com/sighupio/furyctl/issues/392)] The RULE column of `furyctl diff` tells what `furyctl apply` does with each change, from the rules of the distribution: `blocked` (the apply stops), `needs confirmation` (the apply asks before it continues) or `migration` (the apply runs a migration). An empty RULE cell means that no rule matches the change, not that the change has no effect. When the distribution has no rules file for the kind, or the file cannot be read, the table has no verdicts and its last line says why, as `furyctl apply` skips its rule checks in that case.
- [[#392](https://github.com/sighupio/furyctl/issues/392)] On a terminal narrower than the table, `furyctl diff` narrows the CURRENT, NEW and FIELD columns so that the verdict (`✗ blocked`, `! needs confirmation`, `· migration`) is always shown in full; only the explanation of the rule is cut. A file, a pipe or `--no-tty` gets every value in full and no colour. The `NO_COLOR` environment variable turns the colour off.
- [[#392](https://github.com/sighupio/furyctl/issues/392)] `furyctl diff` and the debug log of `furyctl apply` no longer show secret values. A value is printed as `(hidden)` when the name of its field contains `pass`, `secret`, `token`, `key`, `credential` or `authorization`, or when the field is known to hold credentials: Helm `set` values, Dex `bindPW`, Alertmanager webhook URLs, `remoteWrite` headers, custom patches, logging custom outputs, the encryption and cloud configuration, the HAProxy configuration, iPXE commands, node file contents and systemd units. The user and password of a URL are hidden too. The errors of the preflight of `furyctl apply` and `furyctl diff` about an immutable or unsupported change print `(hidden)` in place of the values of such a field.
- [[#806](https://github.com/sighupio/furyctl/pull/806)] The new flag `--config-only`, or `configOnly: true` in the `diff` section of `flags`, makes `furyctl diff` print only the CONFIG table, with exit code 0 when it can read the stored configuration. It downloads no dependency, runs no preflight and renders nothing.

### Immutable, OnPremises and KFDDistribution

- [[#806](https://github.com/sighupio/furyctl/pull/806)] `furyctl diff` now shows the Kubernetes resources that an `apply` would create, update or delete, after the CONFIG table. It prints one report on the standard output: the CONFIG table, then the `Distribution` section and one section for each kustomize plugin and each helm release. Each change is one line, `+` for a create, `~` for an update and `-` for a delete. Control characters in a name or a reason are printed as `?`, and format characters such as bidirectional overrides and zero-width spaces are dropped, as in the CONFIG table. The report ends with the plan, and it warns about each Namespace or CustomResourceDefinition that the `apply` would delete with everything in it. A line `Not shown:` lists what the report does not cover: the cleanups, migrations and upgrade steps that `apply` runs outside kapp, the resources that kapp may replace, and the plugins that you removed from the configuration. `furyctl diff` writes nothing to the cluster. The distribution phase is compared with the new `scripts/diff.sh` of the distribution, which kapp runs with `--diff-run`; with a distribution that has no `diff.sh`, furyctl writes that the section is not supported by that distribution and still compares the helm releases. The flags `--phase distribution` and `--phase plugins` limit the report to that phase, and `--phase infrastructure` and `--phase kubernetes` have no plan to show.
- [[#806](https://github.com/sighupio/furyctl/pull/806)] The local side effects of `furyctl diff` are the same as the first steps of `apply`. It runs the preflight, which on Immutable and OnPremises connects to the nodes over SSH and writes `admin.conf` in the run dir. It renders the distribution and the plugins into the same run dir as `apply`, so it takes the same lock file as `apply`: `diff` stops with the lock file error, before it writes anything, while an `apply` of the same cluster runs, and `apply` stops in the same way while `diff` runs. The lock file is removed when `diff` ends, also on an error or a Ctrl-C. For the helm releases it runs `helmfile init`, which installs the helm plugins and adds the helm repositories on the machine, as `apply` does. It downloads and validates the dependencies as `apply` does; `--airgap-bundle` skips the download.
- [[#806](https://github.com/sighupio/furyctl/pull/806)] Before it runs the `scripts/diff.sh` that the distribution renders, for the distribution or for the kustomize plugins, `furyctl diff` checks that the script is read-only. It refuses the script when a `kapp deploy` has no `--diff-run` or has `-y` or `--yes`, or when the script calls `kapp delete`, a writing `kubectl` command (`apply`, `create`, `delete`, `patch`, `replace`, `edit`, `scale`, `annotate`, `label` and similar), `helm install`, `upgrade` or `uninstall`, or `helmfile apply`, `sync` or `destroy`, by name, by path or through a variable such as `$kubectlbin`. The section then says `not compared: the diff script of the distribution is not read-only:` with the line and the reason, the script does not run and the exit code is 1. The check reads the script line by line and does not follow other variables, functions or files that the script calls. The `helmfile diff` that furyctl runs for the helm releases is checked in the same way: it must be a `diff` with `--suppress-secrets`.

## Bug fixes 🐞

### All kinds

- [[#806](https://github.com/sighupio/furyctl/pull/806)] The temporary folder that holds the merged configuration while furyctl renders a phase is now removed also when a signal (Ctrl-C) stops furyctl during the render. Before this release it stayed in the temporary directory, with the secrets of the configuration.

## Breaking Changes 💔

### All kinds

- [[#392](https://github.com/sighupio/furyctl/issues/392)] The output format of `furyctl diff` changed. Before this release the command printed one `.path: old -> new` line for each change. It now prints the CONFIG table, and scripts that parse the old lines must be changed. With no changes it prints the line `CONFIG   no changes`, where before it only wrote a log message. With `--config-only` the exit code is the same as before; without it, see the next item.
- [[#806](https://github.com/sighupio/furyctl/pull/806)] `furyctl diff` without `--config-only` exits with 1 when a section of the report could not be compared, for example when the cluster is not reachable, when the preflight fails or when a diff command fails. When a step fails before the resources are compared, for example the dependency download, the validation of the configuration file or the render of the configuration, `furyctl diff` still prints the CONFIG table first, then the error as the reason why the resources were not compared, and exits with 1. Before this release it exited with 0 when it could read the stored configuration. A script that relies on the exit code or parses the output must give `--config-only`. Sections that are out of scope, like the resources of an EKSCluster, or not supported by an old distribution, do not change the exit code.
- [[#806](https://github.com/sighupio/furyctl/pull/806)] `--distro-patches` caveat of `furyctl diff`. The distribution phase is rendered with the `scripts/diff.sh` template, which shares the `define` blocks of `_helpers.tpl` with `apply.sh`. A patch that replaces `_helpers.tpl` must carry the new `define` blocks, or the render of `apply.sh` breaks. A patch that changes `apply.sh.tpl` is not mirrored by `diff.sh`, so the report does not show what that change does.

### EKSCluster

- [[#806](https://github.com/sighupio/furyctl/pull/806)] `furyctl diff` does not compare the resources of an EKSCluster yet. Its Distribution and plugins sections say `not compared: EKSCluster is not supported by furyctl diff yet`, only the configuration is compared, and the exit code is 0 when that comparison succeeds.
