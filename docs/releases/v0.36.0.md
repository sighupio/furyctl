# furyctl release v0.36.0

Welcome to the latest release of `furyctl` maintained by SIGHUP by ReeVo team.

This release adds support for SIGHUP Distribution v1.36.0, including its new Utilities core module, and for the v1.35.2 and v1.34.3 patch releases. It also brings new commands, like `furyctl create secrets` and `furyctl renew kubeconfigs`, some user experience improvements like better output for long-running tasks, auto-detection of the default StorageClass and re-apply of the distribution phase, and better upgrade status tracking. The release also includes several refinements for the recently introduced Immutable kind.

Note that this release includes some breaking changes that correct behavior that should not have been allowed before.

## New features 🌟

### All kinds

- [[#756](https://github.com/sighupio/furyctl/pull/756)] The new `furyctl create secrets` command creates the random secrets that a configuration file needs. For example, Pomerium needs four secrets when the authentication provider type is `sso`. It writes one file for each secret and the `--update-config` flag writes the `{file://<path>}` references in `furyctl.yaml` for you. For the components, the flags and the behavior of each one, see `furyctl create secrets --help`. For OnPremises and Immutable, the command can also create the `EncryptionConfiguration` object for etcd encryption at rest.
- [[#772](https://github.com/sighupio/furyctl/pull/772)] furyctl now shows the last 10 lines of output of long-running tasks in a region of the terminal, and removes them when the task completes. The region is off with `--debug`, `--no-tty` and `--log stdout`.
- [[#783](https://github.com/sighupio/furyctl/pull/783)] Immutable, OnPremises and KFDDistribution: when a default StorageClass is available after the distribution or plugins phase, furyctl applies the distribution phase again. One `apply` now installs the packages that need storage on a new cluster.
- [[#807](https://github.com/sighupio/furyctl/pull/807)] furyctl no longer tracks analytics. The `--disable-analytics` (`-d`) flag, the `disableAnalytics` key of `furyctl.yaml` and the `FURYCTL_DISABLE_ANALYTICS` environment variable have no effect, and furyctl writes a deprecation warning when you use them. A future version will remove them.

### OnPremises and Immutable

- [[#741](https://github.com/sighupio/furyctl/pull/741)] furyctl now checks the PKI folder from the configuration file before an apply. When the folder or one of its files is absent, the apply stops. Before this release, the apply failed later, inside an Ansible task, with an unclear message. `furyctl validate config` does the same check, so a pipeline that validates a configuration now needs the PKI folder on that machine.
- [[#745](https://github.com/sighupio/furyctl/pull/745)] The new `furyctl renew kubeconfigs` command renews the kubeconfig files of the admin and of the users in `spec.kubernetes.advanced.users.names`. You can also give a list of names to renew only some of them. A user that you add to the configuration file gets a kubeconfig file without an apply of the kubernetes phase.

### Immutable

- [[#779](https://github.com/sighupio/furyctl/pull/779)] The infrastructure phase no longer waits for the machines to boot when every node answers and no change needs a node provisioned again. Before this release, every apply on a running cluster stopped at the assets server until you pressed ENTER. To provision a node again, erase its disk and power it off before the apply, then boot it from the network while furyctl waits.
- [[#785](https://github.com/sighupio/furyctl/pull/785)] The table of the node bootstrap status now has a SOURCE IP column. The column shows the IP address from which each node sent its last status. Use it to find a node that boots on an unexpected network or NIC.

### EKSCluster

- [[#778](https://github.com/sighupio/furyctl/pull/778)] While `terraform init`, `plan`, `apply` or `destroy` runs, furyctl now shows the last 10 lines of output in the same region as the other long-running tasks. For `apply`, furyctl shows only the message of each JSON line.

## Bug fixes 🐞

### All kinds

- [[#743](https://github.com/sighupio/furyctl/pull/743)] `apply --start-from` now stops when the configuration has changes to a phase before the selected one. Before this fix furyctl skipped those changes and wrote the new configuration to the cluster, so the change was lost and the next `diff` did not show it as pending.
- [[#746](https://github.com/sighupio/furyctl/issues/746)] A flag on the command line now has precedence over the same flag in the `flags` section of `furyctl.yaml`, as documented. Before this fix, `diff`, `create config`, `get cluster-info` and `get upgrade-paths` gave the precedence to the configuration file.
- [[#746](https://github.com/sighupio/furyctl/issues/746)] The `validate`, `download`, `connect`, `renew` and `dump` sections of the `flags` field of `furyctl.yaml` now work. Before this fix furyctl dropped them or stopped with `unsupported flags command`. furyctl no longer accepts a `tools` section, because it has no `tools` command.
- [[#750](https://github.com/sighupio/furyctl/issues/750)] The `flags` section of `furyctl.yaml` now accepts every flag of its commands. Before this release furyctl stopped with `flag 'X' is not supported`, although the command has the flag.
- [[#758](https://github.com/sighupio/furyctl/issues/758)] furyctl now removes the temporary copy of the distribution when the command ends, also on an error and on SIGINT or SIGTERM. Before this fix, each command left a `furyctl-*` folder in the temporary directory. An interrupted download also no longer leaves an incomplete distribution in `.furyctl/cache` for later commands to use.
- [[#762](https://github.com/sighupio/furyctl/pull/762)] furyctl now invalidates its local cache when new commits land upstream.
- [[#780](https://github.com/sighupio/furyctl/pull/780)] furyctl now writes the error that stops a command to the log file, and not only to the terminal.
- [[#781](https://github.com/sighupio/furyctl/pull/781)] The mise that furyctl bundles no longer reads your own mise configuration or your `MISE_*` and `__MISE_*` environment variables. Before this fix it read the settings of `~/.config/mise`, `/etc/mise`, the `mise.toml` files of the current directory and its parents, and the environment.
- [[#782](https://github.com/sighupio/furyctl/pull/782)] On SIGINT or SIGTERM, furyctl now stops the tools that it runs, for example ansible, terraform and kapp, and waits for them to exit. Before this fix furyctl exited at once, and the tools stopped abruptly at their next output. terraform could then keep the state lock.

### OnPremises and Immutable

- [[#776](https://github.com/sighupio/furyctl/pull/776)] The ansible that furyctl installs now works when the `--outdir` path contains a symlink, for example `/tmp` on macOS. Before this fix the link to the ansible venv was broken in that case, and each playbook failed with `no such file or directory`.
- [[#793](https://github.com/sighupio/furyctl/pull/793)] If `apply --upgrade` stops before it completes, `apply --upgrade-node <host>` now stops with a message that names `furyctl apply --upgrade --skip-nodes-upgrade` to complete the upgrade. Before this fix, the message was `upgrade flag not set by user`.
- [[#795](https://github.com/sighupio/furyctl/pull/795)] `apply --upgrade-node <host>` now stops when the configuration file has changes, and names the command to run first. Before this fix, furyctl stored the changes as applied, so a later `apply` or `diff` did not see them.

### Immutable

- [[#759](https://github.com/sighupio/furyctl/pull/759)] furyctl now shows the butane-to-ignition translation errors.
- [[#764](https://github.com/sighupio/furyctl/pull/764)] furyctl no longer panics when it resumes an upgrade from a state that an older furyctl version stored.
- [[#766](https://github.com/sighupio/furyctl/pull/766)] `apply --upgrade --skip-nodes-upgrade` now records the worker nodes that it does not upgrade. Before this fix, the next `apply --upgrade` found no difference between the versions and did not upgrade those nodes.
- [[#767](https://github.com/sighupio/furyctl/pull/767)] `apply` no longer fails with `error during server shutdown: context deadline exceeded` after the machines boot.
- [[#770](https://github.com/sighupio/furyctl/pull/770)] `apply --phase distribution` and `apply --phase plugins` now stop when the cluster does not exist. Before this fix they applied to the cluster of the current kubeconfig context.
- [[#774](https://github.com/sighupio/furyctl/pull/774)] The preflight check now reads every host, and not only the control plane hosts. When other hosts belong to a cluster and no control plane host gives its kubeconfig, the apply now stops and names each host that does not answer.

### OnPremises

- [[#739](https://github.com/sighupio/furyctl/pull/739)] The preflight check now tells a cluster that does not exist yet from any other preflight failure.
- [[#754](https://github.com/sighupio/furyctl/pull/754)] After `apply --upgrade --skip-nodes-upgrade`, a later `apply --upgrade` upgrades only the pending or failed worker nodes, one at a time, and an interrupted upgrade continues from the remaining nodes. While worker nodes are pending, a plain apply stops, and the partial upgrade options stop unless you give `--force upgrades` or `--force all`.
- [[#787](https://github.com/sighupio/furyctl/pull/787)] `furyctl delete cluster` no longer deletes the distribution from the cluster of the current kubeconfig context when the preflight check finds no cluster. It now skips the distribution phase and runs the kubernetes phase only, and `furyctl delete cluster --phase distribution` stops with an error.

## Breaking Changes 💔

### All kinds

- [[#750](https://github.com/sighupio/furyctl/issues/750)] furyctl no longer accepts `create.provider`, `create.name`, `create.version`, `delete.startFrom` and `delete.autoApprove` in the `flags` section of `furyctl.yaml`. No command has these flags, so they did nothing. Remove them, otherwise every furyctl command in that directory stops with `flag 'X' is not supported`.

### Immutable

- [[#764](https://github.com/sighupio/furyctl/pull/764)] `apply --upgrade-node <host>` now stops when you give `--phase`, `--start-from` or `--post-apply-phases` with it. Before this release these flags did no extra work. Give `--upgrade-node` alone.
